# パレット以外の面

パレット（[`palette.md`](palette.md)）を支える面。いずれも `entrypoints/` が container、見た目は `components/`。

---

## 1. 接続シート（API キーの貼り付け先）

接続は **API キーだけ**。OAuth は Backlog 側に `scope` も PKCE も無く、権限を絞る利点が存在しない
（`backlog-facts.md` §6.4、`mvp:docs/implementation-plan.md` §10.0）。副経路としての OAuth も **UI には出さない**（§1.3、決定の記録 2026-09-13）。

### 1.1 導線

```
パレットで「このスペースを接続」↵
  → そのスペースの API キー発行ページ（/EditApiSettings.action#bp-connect）へ遷移
  → content script がフラグメントを見て
      a. Backlog のメモ欄に「Backlog Palette」を入力しておく（後からキーの用途が分かるように）
      b. 貼り付けバーを拡張ページの iframe として**画面下部の中央**に横長で出す
  → 利用者がキーを発行し、表示されたキーをコピーしてシートに貼る
  → ↵ または「接続」で Service Worker へ送る
  → 完了表示。シートは閉じられる
```

- **キーをページから自動で読み取らない。** 読むのは人。拡張が用意するのは貼り付け先だけ
- **貼り付け先をページ側の DOM に作らない。** キーが Backlog のページのコンテキストを通らないように、拡張ページの iframe で出す
- どのスペースに繋ぐかはシート（拡張ページ）が `tabs.query` でタブ URL を読んで決める。ページから送られたホスト名は使わない
- メモ欄の入力は**フォームが後から描画されても**効くようにする（MVP は一度きりの探索で失敗した）。見つからなければ何もしない

### 1.2 シートの状態

| 状態 | 見え方 | 操作 |
|---|---|---|
| 入力待ち | 横長のバー。パスワード型の入力欄と「接続」ボタン（空のときは無効）だけ。見出し・手順・注記は置かない（パレットから遷移してきているので文脈は分かっている） | `↵`（変換中を除く）／ボタンで送信 |
| 送信中 | ボタン無効 + スピナー | — |
| エラー | バーの中に赤字で理由（「キーが正しくありません」「このスペースに接続できませんでした」）。高さは変えない | 直して再送 |
| 完了 | バーの中に「{表示名} に接続しました」と閉じるボタン | `Esc` または閉じるで消える |

- シートが開いた時点で入力欄にフォーカス
- 接続完了時に `GET /api/v2/rateLimit` と `GET /api/v2/projects` を取り、上限とプロジェクト一覧を初期化する（UI には出ない）

### 1.3 OAuth（副経路。UI には出さない）

- 接続バーに OAuth のボタンは**置かない**（2026-09-13 の M1 目視で決定。使う場面が無い）。認可フロー自体は Service Worker に残してよいが、Phase 1 の面からは呼べない
- 1 つの client_id で全スペースを認可できる（`backlog-facts.md` §6.5）。スペースごとの登録は要らない
- `client_secret` は配布物に含める（決定済み）。**配布前にローテーションする。** MVP のシークレットはチャットを通っている
- 失効（401）はパレットの `status` 行から再接続へ。認可フローとリフレッシュは Service Worker が持つ（`tech-stack.md` §2）
- 設定画面の一覧には方式（API キー／OAuth）を出す

## 2. 設定画面（オプションページ）

1 カラム。保存ボタンは無く、変えた項目をその場で書き戻す。

| セクション | 項目 | 挙動 |
|---|---|---|
| 接続しているスペース | 一覧: アイコン、表示名、ホスト、プロジェクト数、最終同期、状態マーカー（接続済み／要再接続）。方式は出さない（API キーだけ） | 「再接続」→ そのスペースの接続導線へ。「削除」→ 1 回目で「本当に削除」に変わり、2 回目で削除。キー・トークン・そのスペースの索引を消す |
| | 0 件のとき | 案内「Backlog のページで ⌘K を押すと、その場で接続できます」 |
| 表示 | 配色: システムに追従／ライト／ダーク | 即反映 |
| | 言語: ブラウザに従う／日本語／English | 即反映。既定はブラウザの UI 言語（§9） |
| スペース | 「Enterprise のカスタムドメインを追加」入力欄 | ホストを入れて追加 → `permissions.request({ origins })` → 許可されたら content script を動的登録し、そのホストでも `⌘K` が効く（§8） |
| 学習 | 「並び順の学習」トグル | オフにすると行動ログの記録と frecency の反映を止める。既存のログは消さない |
| | 「履歴を消去」 | 1 回目で確認、2 回目で消去。行動ログ・表示キャッシュ・検索履歴・クエリ辞書を消す。接続とキーは残す。完了後に「消去しました」 |
| ブラウザ履歴 | 「ブラウザ履歴から最近の課題を取り込む」トグル + 権限の説明 | オンにすると `permissions.request({ permissions: ['history'] })`。拒否されたらトグルは戻る。許可後、過去 90 日の Backlog の閲覧を表示キャッシュに取り込む（1 回限り） |
| ショートカット | 現在の割り当て（`⌘K`）と「変更する」リンク | `chrome://extensions/shortcuts` へ。ページ内では変えられない。Firefox は `about:addons` の管理画面 |
| 利用状況 | 「利用状況の送信」トグル（既定オン） + 送る内容の説明 | 送るのはイベント種別と集計値だけ。クエリ・件名・課題キーは送らない（§10） |
| このアプリについて | バージョン、「API キーは端末内の拡張機能ストレージに保存されます。外部には送信しません」、リポジトリへのリンク | — |

MVP にあった「既定サーフェス（モーダル／サイドパネル）」と「課題キー優先」は**置かない**。前者はパネルが検索の面でなくなったため、後者は効果が説明できないため。

## 3. content script の見え方（ページ側で起きること）

利用者から見える振る舞いだけを書く。実装の線引き（content script は DOM を作らない、メッセージは `open` / `close` の 2 種）は
`tech-stack.md` §2 にある。

| 場面 | 振る舞い |
|---|---|
| Backlog のページを開いた | パレットの iframe を非表示で先行注入する。`⌘K` → 表示まで 100ms 以内 |
| `⌘K` | **content script で捕捉する**（D-10）。`commands` に既定キーを登録すると Backlog 以外のサイトでも `⌘K` を奪うため登録しない。Backlog 本体のエディタやテキスト入力にフォーカスがあるとき、および Backlog 自身が `⌘K` を使う画面では捕捉しない（未決 #4。M3 の実機確認で境界を決める） |
| 課題・Wiki・ドキュメント・プロジェクトのページを開いた | URL とタイトルから表示キャッシュに記録する。件名は `document.title` から取り、形式が合わなければ**課題キーだけ**を記録する。本文・コメントは読まない |
| `#bl-search=` を持つ URL を開いた | パレットを開いて検索を復元する（`palette.md` §7.6） |
| `#bp-connect` を持つ API キー発行ページを開いた | メモ欄を埋め、接続シートを出す（§1） |
| 対象ドメイン | `*.backlog.jp` `*.backlog.com` `*.backlogtool.com`。apex・`www`・`support-*` は除外（`backlog-facts.md` §4.3）。設定で追加したカスタムドメインは動的登録（§8） |

## 5. サイドパネル（詳細検索の面）

パレットは**語とスコープだけ**で探す面。サイドパネルは**条件を付けて探す面**（D-1・D-9）。
本文のプレビューは持たない。中身は Backlog のページを開いて見る。結果と検索状態はページを行き来しても残る。

### 5.1 開く経路

| 経路 | 状態 |
|---|---|
| パレットで `⌘→`（入力に語があるとき）、または 0 件時の `panel` 行 | 語とスコープを引き渡し、その条件で検索を起動して開く。パレットは閉じる。パネルの入力欄にフォーカス |
| ツールバーのアイコン（Backlog のタブ） | 前回の状態で開く。何も無ければ入力欄と最近の検索だけ |
| `#bl-search=` を持つ URL（条件つき） | パネルで復元する。条件を持たない共有 URL はパレットで復元する（`palette.md` §7.6） |

### 5.2 構成

```
┌ 検索入力（語）                                       ┐
│ 最近: 決済 / リリース手順 / ログイン                    │ ← 入力欄が空のとき。↑ で直前の語
│ [プロジェクト ▾][種別 ▾][ステータス ▾]                 │ ← 常設フィルターバー。効いている条件は強調
│ [担当者 ▾][更新日 ▾]                                   │    幅が足りなければ折り返す
│ 17 件   ／   課題 12 · Wiki 読み込み中 · ドキュメント 2   │ ← ステータス帯（リストの外。動かない）
├────────────────────────────────────────────────────┤
│ 結果（パレットと同じ行。タブのスペースの中だけ）           │
│ ◇ PROJ-142 決済フローのエラーハンドリング   処理中 · 田中  │
│ ◇ PROJ-118 …                                        │
│ ▦ 決済まわりの仕様メモ                                │
├────────────────────────────────────────────────────┤
│ ↑↓ 移動  ↵ 開く  ⌘↵ 新しいタブ  ⌘⇧C 検索 URL をコピー   │
└────────────────────────────────────────────────────┘
```

1 カラム固定。幅 480px 未満ではフィルターバーを compact（高さと文字を詰める）にする。

### 5.3 フィルターバー

条件はすべて AND、各条件は**単一選択**（Backlog の検索は OR ができない。技術的制約）。OR が要る要求はプリセットで吸収する。

| 項目 | 選択肢 | 備考 |
|---|---|---|
| プロジェクト | すべて／参加プロジェクト | スペースはタブのスペースに固定（D-20）。切り替えはパレットの根で行う |
| 種別 | すべて／課題／Wiki／ドキュメント | |
| ステータス | すべて／**完了を除く**（プリセット）／プロジェクトのステータス各種 | ステータスはプロジェクトごとに ID が違う。プロジェクトが「すべて」のときは組み込み 4 種 + プリセットだけ |
| 担当者 | すべて／自分／未設定 | ユーザー一覧は管理者しか取れない（D-12）ので、名前指定は持たない |
| 更新日 | 指定なし／1 週間以内／1 か月以内／3 か月以内 | |

- 選択肢はラジオとして描き、「1 つだけ選べます」を明示する（複数選べると誤解させると 0 件に落ちる）
- 変更は即座に再検索する（明示的な操作なので Enter を待たない）。到着規則はパレットと同じ（I4）
- 「条件をすべて外す」ボタンをバーの右端に置く。スコープ（スペース・プロジェクト）は外さない

### 5.4 挙動

- 行はパレットと**同じ部品・同じ動作**（`palette.md` §5）。`↵` で遷移、`⌘↵` で新しいタブ。遷移してもパネルは閉じない。`⇥` は補完だけ（パネルにスタックは無い。スコープはフィルターバーで選ぶ）
- 種別単位の進捗・エラーは**ステータス帯**に出す。リストにグループ見出しを差し込まない。認証切れは帯の中に「再接続」
- 入力欄が空で `↑` → 直前の検索語を再入力。最近の検索は入力欄の下に 5 件。`Enter` で検索
- 0 件はパレットと同じ規則の提案行を結果の位置に出す。順序は **条件を外す → プロジェクトを外す（プロジェクトが選ばれているとき）→ 本体検索**。「効いている条件を外す」を先頭に置く（原因の切り分け）
- `⌘⇧C` は条件を含む検索状態の URL をコピーする
- パネルの `⌘K` はパレットを開く（P1）。パネル内のフォーカス移動には使わない

### 5.5 Firefox

`sidebar_action` として同じ UI を出す。サイドバーをスクリプトから開く API が無いため、`⌘→` と `panel` 行は
**サイドバーが開いているときだけ**フッターと候補に出す（出していないキーは無い。I2）。

## 6. Backlog 以外のページ

`⌘K` は効かせない（D-10）。他のサイトの `⌘K` を奪わないため、ブラウザの `commands` にキーを登録せず、
Backlog のページの content script で捕捉する。ツールバーのアイコンは Backlog 外のタブでは設定画面を開く。

## 7. Firefox

同じ manifest を `wxt -b firefox` で出し分ける。

- `browser_specific_settings.gecko.id` と `data_collection_permissions` を付ける（AMO の必須項目）
- `sidePanel` 権限は Firefox が知らないので Chrome ビルドだけに入れ、Firefox は `sidebar_action`（§5.4）
- `⌘K` の捕捉は Chrome と同じく content script（`commands` は使わない）
- OAuth の `redirect_uri` は `identity.getRedirectURL()` が別形式を返すため、OAuth アプリに追加登録が要る（人の作業）
- Backlog 外での挙動（§6）は Firefox でも同じ

## 8. Enterprise のカスタムドメイン

- 設定画面の「カスタムドメインを追加」でホストを入れる → `permissions.request({ origins: ['https://{host}/*'] })` → 許可されたら
  `scripting.registerContentScripts` で content script を登録し、`⌘K` が効くようになる
- 接続（§1）は同じ導線。API のベース URL は `https://{host}/api/v2/`
- postMessage の origin 検証と `matches` の判定は「静的な 3 ドメイン ＋ 登録済みカスタムドメイン」で行う
- **未確認**: カスタムドメインの実際の形式（`backlog-facts.md` §5-12）。実機で確認できるまでは「任意のホスト 1 つ」として扱う

## 9. 言語

- 日本語と英語。ブラウザの UI 言語に従い、設定で上書きできる
- 部品は文言を `labels` として受け取る（`ui-components.md` §1）。辞書は `components/labels/{ja,en}.ts`。ドメイン語（ステータス名・プロジェクト名）は Backlog が返す値をそのまま出す
- キー記号は言語で変えない（`⌘` `↵` `⌫`）。Windows / Linux では `⌘` を `Ctrl` に置き換える（言語ではなく OS の判定）
- ストア掲載文・OAuth アプリの説明文は日英とも確定稿を使う（`mvp:docs/reference/backlog-cmdk-extension-plan.md` §10、`mvp:docs/oauth-app.md`）

## 10. 利用状況の計測

「使われていないのか、見つけられていないのか」を区別するために最初から入れる。**送るのはイベント種別と集計値だけ。**
クエリ・件名・課題キー・URL は送らない。設定でオプトアウトできる。

| 指標 | 何が分かるか |
|---|---|
| 起動回数 / 日 | 使われているか |
| 起動 → 遷移の完了率、遷移までの打鍵数 | 目的の場所に着けているか |
| 空状態からの選択率 | 何も打たずに済んだ割合 |
| 検索の起動回数と 0 件率、本体全体検索へ逃げた率 | 検索が足りているか |
| `⌘→` と検索 URL コピーの回数、パネルでの条件変更の回数 | 詳細検索と共有が使われているか |
| 面別の利用比（パレット／パネル） | どこで使われているか |

送信先と保持期間は人が決める（`milestones.md` M7）。決まるまでは送信せず、集計だけをローカルに持つ。
