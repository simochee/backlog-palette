# 体験の原則と不変条件

`mvp:docs/implementation-plan.md` §2.2 の原則 P1〜P7 を引き継ぎ、MVP の実機評価で見つかった穴を
不変条件として足す。**原則は判断の基準、不変条件は機械的に検査する契約。**

## 1. 想定ユーザー

1. **課題キーで会話する人**（開発者・PM）。`PROJ-1234` へ 1 日に何十回も飛ぶ
2. **複数スペース・複数プロジェクトを横断する人**（受託 PM・情シス・管理者）
3. **非開発職のヘビーユーザー**（ディレクター・営業事務）。記号や暗記を要求すると離脱する

**3 番目の人が迷わないことを最優先**にする。密度・文言・ヒント表示の判断基準はここ。

## 2. 原則（判断の基準）

| # | 原則 | 具体的な含意 |
|---|---|---|
| P1 | 覚えるのは `⌘K` だけ | プレフィックス（`>` `#`）は加速装置。無しでも同じ結果に到達できる |
| P2 | 移動と検索が先。書き込みは後 | Phase 1 に破壊的操作を入れない |
| P3 | 文脈を並びに反映する | 現在プロジェクト・直近に開いたもの・頻度が並びに効く |
| P4 | 日本語 IME を一級市民として扱う | 変換中の Enter で遷移しない。変換中も候補は更新する。全角記号を受理する。かな入力でページが引ける |
| P5 | ヒントは省かない | フッターのキーヒントは常時表示。押した後も消さない |
| P6 | 筋肉記憶を壊さない | 同じ入力 → 同じ結果 → 同じ位置。非同期の到着で選択行を動かさない |
| P7 | 本体より主張しない | Backlog のページに重なる前提。暗転と影だけで層を示す |
| **P8** | **打った語の結果はその場に出る** | 検索結果はパレットの中に出る。別の面へ送らない（評価 §8.3） |

## 3. 不変条件（機械的に検査する契約）

MVP は「UI が約束したキーに処理が繋がっていない」壊れ方を 3 箇所でした（評価 §8.2）。
個別のテストではなく、**構造として破れない形**にする。

### I1. 表示されている行には、必ず対応する動作がある

- 行の `hints`（`↵` `⌘↵` `›`）は container が**動作から導出**する。UI に自由な文字列で渡さない
- 動作を持たない行は `hints` が空で、Enter を押しても何も起きないことが**見た目から分かる**（ヒントが出ない）
- 検査: 全 story で「ヒントを持つ行に Enter → `onAction` が呼ばれる」を共通の play function で回す（[`ui-components.md`](ui-components.md) §5）

### I2. フッターが出しているキーには、必ず対応する動作がある

- フッターのヒントは `KeyBinding[]` から**描画される**。ヒントの文言を手で書く経路を作らない
- 検査: 全 story で「フッターに出ている各キーを押す → 対応するハンドラが呼ばれる」を共通の play function で回す

### I3. Tab でフォーカスはパレットから出ない

- 補完できる行が無くても `Tab` は既定動作を止める。フッターに `⇥` が出ていないときも同じ

### I4. 非同期の到着で選択行は動かない

- 後から届いた行は**選択行より下にだけ**入る。上に入るべき行は「保留」として予告し、選択が先頭に戻ったときに合流する

### I5. 変換中のキーは候補リストに届かない

- `isComposing === true` の `Enter` `↑` `↓` `Tab` `Escape` は捨てる。変換確定の Enter で遷移しない

### I6. エラーは行に閉じる

- 未接続・認証切れ・レート超過・オフラインは**行またはセクションの補足**として出す。パレット全体をエラー画面に切り替えない

### I7. 認証情報は UI に渡らない

- `components/` は拡張機能 API を import しない（Storybook のビルドが検査する）。トークン・API キーは props にも現れない

## 4. テストの書き方（評価 §3.1 の教訓）

- **状態ではなく結果を問う。** `toBeFocused` や `textContent` ではなく、「押したらハンドラが呼ばれた」「打った文字が入力欄に入った」を検査する
- story の `name` に仕様を日本語で書く。「Enter で選択行の onAction が呼ばれる」のように、読めば入出力が分かる名前にする
- 仕様が固まっていない振る舞いには story を書かない。書けないことが未定義のサイン
