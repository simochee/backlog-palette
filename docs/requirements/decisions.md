# 要決定事項と決定の記録

**着手前に §1 を埋める。** 各項目に推奨案を付けてあるので、異論が無ければ「推奨どおり」と書くだけでよい。
決めたら該当する文書の「推奨」を「決定」に書き換え、ここに日付と理由を残す。

---

## 1. 要決定（Phase 1 の UI に効くもの）

### D-1. サイドパネルを Phase 1 に含めるか

- **推奨: 含めない。** 検索結果はパレットに出す（原則 P8）。MVP のサイドパネルは「モーダル＝行く／パネル＝探す」の分離を前提に作られ、その前提が実機で否定された（評価 §8.3）。「詳しく見る面」としての価値（プレビュー・結果の保持）は否定されていないが、パレット単体で成立させた後に、狭い面で何が足りないかを見てから設計する
- 影響: UI の面が 1 つ減る。フィルターバー・ステータス帯・種別タブ・プレビューは作らない。`⌘→`（昇格）も無くなる
- 別案: パネルを「選択行のプレビュー」専用の面として残す。この場合パレットとパネルの同期（選択の追従）が新たな仕様になる

### D-2. 検索の起動をどうするか

- **推奨: Enter で明示。** 打鍵ごとの自動検索はしない。Wiki がプロジェクト単位の並列になるため、全スペースで 1 回の検索が search 枠（150 / 分）を数十消費しうる。IME 変換中の中間文字列で叩く無駄も避けられる
- 別案: 入力停止から 400ms で自動起動。単一スペース + 単一プロジェクトのスコープに限れば予算に収まる可能性がある。実機で計測してから足す

### D-3. 検索結果をどこに出し、選択をどう動かすか

- **推奨: 検索行の直下にセクションを挿し、起動と同時に選択をプレースホルダ行へ移す。** `語 → ↵ → ↵` で先頭ヒットが開く。候補セクションは下に残す
- 別案: 候補を消して結果だけにする。戻る操作（入力を消す）が要り、候補にあった行へ行けなくなる

### D-4. プロジェクト行の Enter

- **推奨: プロジェクトホームへ遷移。** 「プロジェクトを切り替える」という利用者の言葉に一致し、MVP と同じ。スコープを狭める操作は Phase 1 では持たない（スコープは開いたときの文脈と `⌫` で決まる）
- 別案: スコープに積む（`›`）。プロジェクト配下のページへ 2 段で行けるが、切り替えたいだけの人に 1 打鍵増える

### D-5. コピー後にパレットを閉じるか

- **推奨: 開いたまま、フッターにトーストを 2 秒。** 閉じるとトーストの出し先が無い（パレットは iframe で、ページ側に DOM を作らない）
- 別案: トースト表示後 1.5 秒で自動で閉じる。連続コピー（キー → URL）ができなくなる

### D-6. Esc はスコープを外すか

- **推奨: 外さない。スコープだけのとき Esc は閉じる。** スコープを外すのは `⌫` の 2 段のみ。「Esc で閉じる」が壊れると逃げ道が無くなる
- 別案: MVP の裁定 D3 どおり Esc も右端を 1 段外す。閉じるのに最大 3 回押す

### D-7. マウスホバーで選択を動かすか

- **推奨: 動かさない。クリックは Enter と同じ。** キーボード操作中にマウスが触れて選択が飛ぶ事故を避ける

### D-8. 開いているときの ⌘K

- **推奨: 閉じる（トグル）。** ⌘K が「出す・しまう」の 1 キーになる

### D-9. パレット内に絞り込み（種別・ステータス・担当者）を持つか

- **推奨: 持たない。** 条件チップ（MVP のモック A8）も、フィルターバーも Phase 1 から外す。検索対象は課題・Wiki・ドキュメントの 3 種固定、条件はスコープのみ。0 件時に「広げる」提案だけ出す
- 別案: `処理中 決済` のようなステータス名の検出（MVP の `detectConditions`）を条件チップとして出す。検出語彙の UX が未決のまま

### D-10. Backlog 以外のページで ⌘K を効かせるか

- **推奨: 効かせない。** Phase 1 は Backlog のページ上だけ。ツールバーのアイコンは Backlog 外では設定画面を開く
- 別案: ポップアップとして同じ UI を出す。文脈（現在スペース）が無いのでスコープと空状態の定義が別に要る

### D-11. 文言の多言語化

- **推奨: Phase 1 は日本語のみ。** ただし部品の文言は props で差し替えられる構造にし、既定値として日本語を持つ。i18n の仕組みは Phase 2
- 影響: `components/` に日本語の既定文言が入る。ドメイン語（ステータス名など）は最初から props

### D-12. `@ユーザー` プレフィックス

- **推奨: Phase 2。** `GET /api/v2/users` は管理者ロールが要り、一般ユーザーではプロジェクト単位の積み上げになる。Phase 1 は `>`（コマンド）と `#`（プロジェクト）だけ

### D-13. 候補リストの挙動レイヤー

- **推奨: `CandidateList` は自前で書く**（`role="listbox"` + `aria-activedescendant`、controlled な選択）。MVP は react-aria-components の `Autocomplete` を土台にし、仮想フォーカスの持ち越し・`Escape` の消費・`isComposing` の無視をキャプチャ段階で先回りして潰す形になった。要件が「選択は container が持つ」なので、内部状態を持つライブラリと相性が悪い
- 別案: react-aria-components を続ける。MVP の `surfaceKeys.ts` の対処を全部持ち込む

### D-14. 表示キャッシュの stale-while-revalidate

- **推奨: Phase 1 で入れる（UI には影響しない）。** 空状態の件名がずれたまま残るのを防ぐ。表示した行だけを裏で再取得し、ステータス・担当者を差し替える。差し替えで**行の位置は動かさない**

## 2. 決定済み（MVP から継承。理由は `mvp:docs/implementation-plan.md` §3・§19）

| 決定 | 要点 |
|---|---|
| スタックモデル | スコープは列挙値ではなくパス。右端から 1 段ずつ外す。コマンド階層も同じスタック |
| `Tab` は候補の補完 | スコープ切替には使わない。IME と競合し、フォーカスが出る |
| `⌫` の 2 段 | キャレット先頭のときだけスタックに効く。1 回目は予告、2 回目で外す。入力文字は消えない |
| 全スペース検索はフラット | スペース別のグループ見出しを差し込まない。非同期到着で選択が動く |
| React + 見た目はトークン層 | 見た目の差し替えはトークンと CSS Modules だけで済む構造 |
| 接続の既定は API キー | OAuth は `scope` も PKCE も無く、利点が無い。Phase 1 では作らない |
| `client_secret` は配布物に含める（OAuth を作る場合） | RFC 8252 の public client。`redirect_uri` の一致が実質の防御 |
| 直接ジャンプ行・コマンド名完全一致は個人化で動かさない | 筋肉記憶を守る不変条件 |
| セクションの順序は固定 | 個人化はセクション内の並びにだけ効く |
| 認証情報は Service Worker だけが持つ | UI にも content script にも渡さない |
