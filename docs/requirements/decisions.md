# 要決定事項と決定の記録

§1 の 16 件は 2026-09-13 に 1 件ずつ確認して決めた。覆すときは §3 に日付と理由を残し、該当する文書を直す。
新しく決めることが出たら §1 に番号を足す。

## 0. 判断の前提

開発は Claude Code で進める。したがって **実装の工数・手間を理由にした縮小は行わない。**
範囲を狭める根拠として認めるのは次の 3 つだけ。

1. **製品上の理由**: 原則（`principles.md`）に反する、利用者を迷わせる、検証されていない仮説に立っている
2. **技術的制約**: API・ブラウザ・レートリミットの事実（`../backlog-facts.md`）が許さない
3. **人の判断が要る**: 実機での確認、秘密情報の扱い、ストア提出のように人しかできない工程に依存する

「作ると時間がかかる」「部品が増える」は理由にならない。過去の文書（`mvp:docs/implementation-plan.md` §17 など）が
工数で切ったものは、この基準で見直してある（§3 の 2026-09-13 の記録）。

## 1. 決定（2026-09-13、全 16 件を確認済み）

各項目の「別案」は退けた理由とともに残す。覆すときは §3 に記録する。

### D-1. サイドパネルは「詳細検索の面」

- **決定**: パレットは語とスコープだけで探し、サイドパネルは**条件を付けて探す**。本文のプレビューは持たない。中身は Backlog のページで見る。
  結果と検索状態は残る。`⌘→` で語とスコープを引き渡す。仕様は `surfaces.md` §5
- 退けた案: 「詳しく見る面」（本文の抜粋 + ハイライト）。この拡張の範囲で課題の中身まで見せる必要はない、という製品判断
- 退けた案: MVP のまま「モーダル＝行く／パネル＝探す」。実機で否定された前提に戻る

### D-2. 検索は Enter で明示的に起動する

- **決定**: 検索行で `↵`。打鍵ごとに API を叩かない。Wiki がプロジェクト単位の並列になるため、全スペースで 1 回の検索が
  search 枠（150 / 分）を数十消費しうる（技術的制約）
- 退けた案: 単一プロジェクトのときだけ自動起動。M4 で search 枠の消費を実測した後に再検討してよい

### D-3. 検索結果は検索行の直下。選択は先頭結果へ

- **決定**: 検索行の直下に「検索結果」セクションを挿し、起動と同時に選択をプレースホルダ行へ移す。`語 → ↵ → ↵` で先頭ヒットが開く。候補は下に残す

### D-4. プロジェクト行は `↵` で遷移、`⇥` でスコープに積む

- **決定**: `↵` はプロジェクトホームへ遷移。`⇥` はスコープに積む。あわせて **`⇥` の意味を「実行せずに入力欄へ取り込む」で統一**する:
  `space` / `project` / 2 段階コマンドの行は積む、それ以外の行はタイトルで補完する。MVP の裁定 D1（Tab＝補完）はこの一般化に含まれる
- 退けた案: `⌘↵` で積む。`⌘↵` の意味が行によって変わる

### D-5. コピー後はパレットを開いたまま、フッターにトーストを 2 秒

- **決定**: 閉じるとトーストの出し先が無い（パレットは iframe で、ページ側に DOM を作らない。技術的制約）。連続コピーもできる

### D-6. Esc はスコープを外さない

- **決定**: スコープだけのとき `Esc` は閉じる。スコープを外すのは `⌫` の 2 段だけ。コマンド階層では `Esc` で 1 段戻る

### D-7. マウスホバーで選択を動かさない

- **決定**: クリックは `↵` と同じ。ホバーは選択に影響しない

### D-8. 開いているときの `⌘K` は閉じる

- **決定**: トグル

### D-9. パレットに絞り込み条件を持たない

- **決定**: パレットの検索は語とスコープだけ。種別・ステータス・担当者・更新日の条件はサイドパネルのフィルターバーだけが持つ。
  0 件時にはパレットから「詳細検索で条件を変えて探す」の行でパネルへ渡す
- 退けた案: ステータス名の検出で検索行を 2 つ出す。パレットの役割が曖昧になる

### D-10. `⌘K` は Backlog のページ上だけで効く

- **決定**: 他のサイトの `⌘K` を奪わない（既存機能を損なうサイトがある）。ブラウザの `commands` に既定キーを登録せず、
  Backlog のページの content script で捕捉する。Backlog 外のタブではツールバーのアイコンが設定画面を開く
- 含意: `commands` を使わないので、Backlog 本体のエディタやショートカットとの境界（未決 #4）を M3 の実機確認で決める

### D-11. 日本語と英語を持つ

- **決定**: ブラウザの UI 言語に従い、設定で上書きできる。部品は文言を `labels` として受け取る

### D-12. `@ユーザー` プレフィックスは持たない

- **決定**: スペース全体のユーザー一覧は管理者しか取れない（`GET /api/v2/users`。技術的制約）。プロジェクト単位の積み上げも採らない。
  担当者はサイドパネルのフィルターで「自分／未設定」だけを扱う

### D-13. 候補リストは自前で書く

- **決定**: `role="listbox"` + `aria-activedescendant`、選択は controlled。MVP が react-aria-components で踏んだ 3 つの罠
  （仮想フォーカスの持ち越し・`Escape` の消費・`isComposing` の無視）は内部状態を持つライブラリとの相性から来ている。
  入力欄と競合しない部品（スイッチ・セレクト・ダイアログ）には react-aria-components を使ってよい

### D-14. 表示キャッシュは stale-while-revalidate

- **決定**: 表示した行だけを裏で再取得し、ステータス・担当者・件名を差し替える。行の位置は動かさない。接続済みスペース限定

### D-15. ローマ字 → かな変換マッチを持つ

- **決定**: 正規化の 1 段として入れる。効くのはかなの別名を持つページ・コマンド。読みを持たない件名・プロジェクト名には効かない

### D-16. 遷移パターンによる個人化を持つ

- **決定**: 空状態の「{プロジェクト} のページ」セクション内の並びにだけ効かせる。介入ルール（セクション順固定・完全一致は動かさない・同点のときだけ）の内側

## 2. 決定済み（MVP から継承。理由は `mvp:docs/implementation-plan.md` §3・§19）

| 決定 | 要点 |
|---|---|
| スタックモデル | スコープは列挙値ではなくパス。右端から 1 段ずつ外す。コマンド階層も同じスタック |
| `Tab` は候補の補完 | スコープ切替には使わない。IME と競合し、フォーカスが出る |
| `⌫` の 2 段 | キャレット先頭のときだけスタックに効く。1 回目は予告、2 回目で外す。入力文字は消えない |
| 全スペース検索はフラット | スペース別のグループ見出しを差し込まない。非同期到着で選択が動く |
| 常設フィルターバーは単一選択の AND | Backlog の検索は OR ができない。OR はプリセットで吸収する（サイドパネルに置く。D-9） |
| React + 見た目はトークン層 | 見た目の差し替えはトークンと CSS Modules だけで済む構造 |
| 接続の既定は API キー | OAuth は `scope` も PKCE も無く、権限を絞る利点が無い。OAuth は任意の副経路として持つ（§3） |
| `client_secret` は配布物に含める | RFC 8252 の public client。`redirect_uri` の一致が実質の防御。配布前にローテーションする |
| 直接ジャンプ行・コマンド名完全一致は個人化で動かさない | 筋肉記憶を守る不変条件 |
| セクションの順序は固定 | 個人化はセクション内の並びにだけ効く |
| 認証情報は Service Worker だけが持つ | UI にも content script にも渡さない |

## 4. Phase 2（作らない。理由は工数ではない）

| 項目 | Phase 1 に入れない理由 |
|---|---|
| 課題への書き込み（ステータス変更・担当者・マイルストーン）、お知らせの既読 | 原則 P2。破壊的操作には確認と Undo の設計が要り、その設計を検証する場が Phase 1 の実機評価。読み取り専用で信頼を作ってから |
| 保存済み検索条件の登録 | 課題一覧のクエリ文字列の仕様が未確認（`backlog-facts.md` §5-10）。検索状態の URL 共有（P1 に含む）で代替できるかを見てから |

| Backlog 本体の UI の書き換え | 製品の範囲外 |
