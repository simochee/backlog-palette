# MVP の評価

- 対象: `mvp` ブランチ（2026-09-13 時点）
- 位置づけ: **デザインモックと機能アイデアから直接作った評価用のビルド**。Ideation と Inception を飛ばしているため、要件・ユーザーストーリー・受け入れ条件が存在しない
- この文書の用途: AI-DLC v2 による正式実装への入力

---

## 1. 何が動くか

実機（Chrome）と、偽の Backlog スペースを立てた E2E の両方で確認している。

| 面 | 動くもの |
|---|---|
| モーダル（行く） | ページ移動 / 課題キーの直接ジャンプ / プロジェクト切替 / コピーコマンド 4 種 / 最近開いた項目 / 担当中の課題 / スコープの積み下ろし（`⌫`）/ コマンドの 2 段階 / 未接続スペースの行 |
| サイドパネル（探す） | スペース横断検索 / 常設フィルター / スペース単位の進捗とエラー / プレビュー（ヒット位置で切り出し）/ 検索履歴 / 0 件のときの提案 / 検索 URL のコピー |
| 接続 | API キーの案内つき接続（発行ページへ誘導 → メモ欄を入力 → 貼り付け欄を表示）。OAuth は env があるときだけの任意経路 |
| 設定 | 接続スペースの一覧と削除 / 既定サーフェス / 配色 / 学習のオンオフ / 課題キー優先 / 履歴の消去 / ブラウザ履歴取り込みの権限要求 |

**検証の規模**: ユニット 585 件（core 215 / extension 370）、E2E 37 件。E2E は `--host-resolver-rules` でローカルの HTTPS サーバを `demo.backlog.jp` に見せ、拡張を本番と同じ manifest のままヘッドレスで通している。

## 2. 検証済みの判断

**作り直しても変わらない。**根拠は `docs/backlog-facts.md` と `docs/implementation-plan.md` §3・§19 にある。

### 2.1 Backlog の事実（実測）

| 事実 | 影響 |
|---|---|
| `keyword` は課題の本文とコメント、Wiki の本文にも一致する | クライアント側で本文を照合する重い代替が不要 |
| レートリミットは `GET /api/v2/rateLimit` で実値が取れる（read 600 / search 150 / update 150 / icon 60） | 上限をコードに持たない。接続時に初期化する |
| `GET /wikis` は `projectIdOrKey` 必須、`count` が効かず全件返る。一覧に本文 `content` を含む | 横断検索は参加プロジェクト数の並列になる。キーワード無しの一覧取得はしない |
| `GET /users` は管理者ロールが必要 | ユーザー一覧の先読みは一般ユーザーで破綻する |
| `GET /issues` はパラメータ無しだと 400 | `projectId[]` を型で必須にする |
| OAuth は PKCE 非対応で `client_secret` 必須。`scope` が無い | 権限を絞れない。OAuth の利点が API キーに対して存在しない |
| 1 つの OAuth クライアントで全スペースを認可できる | （OAuth を使う場合）スペースごとの登録は不要 |
| `backlogtool.com` は旧ドメインだが現役 | 対象ドメインに含める |
| Chrome の `*.backlog.com` は apex と www にもマッチする | マーケティングサイトを除外しないと注入される |

### 2.2 設計上の裁定

モックと仕様書の矛盾 6 点を裁定済み（§3）。特に次の 3 つは実装の骨格になっている。

- **スコープは列挙値ではなくパススタック**。コマンド階層も同じスタックに積むので、`Esc` と `⌫` を「右端から 1 段戻す」という 1 本の規則で説明できる
- **`Tab` は候補の補完**。スコープ切替に使うとフォーカス移動を奪い、IME の変換候補と衝突する
- **全スペース検索の結果はフラット固定**。スペース別のグループ見出しを差し込むと、後着スペースの行が選択位置を動かす

### 2.3 途中で覆した判断

- **OAuth を既定にする → API キーを既定にする**（§10.0）。OAuth を選んだ理由は「キーのコピペが不要」だけで、案内つきの導線でその前提が満たせる。一方 Backlog の OAuth には `scope` が無く、権限の絞り込みという本来の利点が存在しない
- **Wiki の一覧に本文が含まれない → 含まれる**。当初の調査が誤りで、Wiki もスニペットを作れる

## 3. 踏んだ罠

**これが MVP から引き継ぐ一番大きなもの。**判断は資料を読めば再現でき、コードは作り直せるが、これらは踏まないと分からず、踏めば必ず同じ時間を失う。

| 罠 | 症状 | 対処 |
|---|---|---|
| WXT の `createIframeUi` で `position: 'overlay'` | wrapper に `width:0/height:0` が付き、**iframe が 0×0 に潰れる**。表示されているのに見えない | `position: 'modal'` を使う。さらに iframe の既定サイズ（300×150）が効くので幅高さを明示する |
| WXT のエントリポイント名の衝突 | `entrypoints/palette/index.html` と `entrypoints/palette.content/` は内部名が同じになり、**content script が警告なしにビルドから消える** | 名前を分ける。ビルド後に `manifest.json` を目で確認する |
| React Aria の仮想フォーカス | 候補が入れ替わっても `aria-activedescendant` が**消えた行を指したまま残る**。Enter が無反応なのに行は選択された見た目 | Enter の宛先を DOM から自分で解決する（実在するフォーカス行、無ければ先頭行） |
| React Aria が `Escape` を消費する | 入力欄のクリアに使われ、パレットが閉じない | キャプチャ段階で先に受ける |
| React Aria が `isComposing` を見ない | 変換確定の Enter で遷移が発火し、↑↓ が IME 候補選択と二重に動く | キャプチャ段階で変換中のキーを止める |
| ダークテーマのセレクタ | `[data-bp-theme][data-bp-scheme="dark"]` は同一要素を要求する。祖先が scheme を持つ内側でテーマ属性を付けると **light が再宣言されて dark が効かない** | 子孫セレクタも併記する |
| `storage.local.clear()` が設定を消す | E2E のテスト間クリアで OAuth 設定まで消え、2 件目以降が notConfigured になった | 配布物の設定はストレージではなく env から読む |
| クリップボードは Service Worker から書けない | DOM を持たず `navigator.clipboard` が無い | 拡張ページ側で書く。クロスオリジン iframe からは埋め込む側の `allow="clipboard-write"` が要る |
| `chrome-launcher` が userDataDir の存在を前提にする | `wxt dev` が `chrome-out.log` の ENOENT で落ちる | プロファイルのディレクトリを先に作る（`server:created` フック） |
| `web-ext` は WXT の optional peer dependency | 入れていないと `wxt dev` は**エラーを出さず**ビルドだけして終わる | 依存に入れる |
| Playwright の既定引数 | `--disable-extensions` が入るため拡張が読み込まれない | `ignoreDefaultArgs: ['--disable-extensions']` |
| Playwright の headless | 既定は Chrome Headless Shell で**拡張を読み込めない** | `channel: 'chromium'` で完全なブラウザの新ヘッドレスにする |
| branded Chrome の `--load-extension` | Chrome 137 以降は無視される（ただし web-ext は CDP の `Extensions.loadUnpacked` を使うので `wxt dev` は影響を受けない） | E2E では Chrome for Testing を使う |
| `selfsigned` v5 | `generate` が async になっている。await を忘れると空のオブジェクトが返る | await する。鍵長と署名アルゴリズムも明示しないと Chrome が拒む |
| pnpm 11 | `package.json` の `pnpm` フィールドを読まない。ビルドスクリプトの許可は `allowBuilds` マップ | 設定は `pnpm-workspace.yaml` へ |

### 3.1 テストの書き方についての教訓

同じ壊れ方を 2 回見逃している。

- **`toBeFocused` は iframe 内の `activeElement` しか見ない**。トップレベルのフォーカスがページに残っていても通る
- **`textContent` の検査は 0×0 の要素でも通る**

いずれも「状態を問う assertion」で、**結果を問う assertion**（打った文字が入力欄に入るか、面の背景色が暗いか）に変えて初めて捕まえられた。

## 4. 意図的に外したもの

MVP の評価の焦点を絞るために外した。**無いのではなく、判断して外している。**

| 外したもの | 理由 |
|---|---|
| i18n / 英語表示 | 評価は日本語話者で行う。文言は Ideation で見直す対象 |
| 利用状況の計測 | 何を測るかは Ideation が決める。先に作ると測る対象を固定する |
| Firefox 対応 | 評価は Chrome。`data_collection_permissions` と `browser_specific_settings.gecko.id` は提出時の話 |
| ブラウザ履歴からの取り込み | 追加権限を要求する。評価の価値に対してリスクが高い（設定画面のトグルと権限要求だけは実装済み、取り込み処理は無い） |
| 表示キャッシュの stale-while-revalidate | 件名のズレは評価で観察すればよい |
| 属性語の条件チップ（モック A8） | `detectConditions` は実装済みだが UI 配線は無い。どこまで検出するかの UX が未決 |
| `⌘→`（モーダルから検索パネルへの昇格） | 同上 |
| CI | 正式実装の持ち物 |
| ストア提出物 | 評価段階では不要 |

## 6. 過剰だと思うもの

正式実装に持ち込む前に取捨してほしい。

- **テスト 585 件は多い。** 「壊れたら利用者が気づかない振る舞い」を守るテスト（スタックの不変条件、ランキングの介入ルール、IME、`§2.3` の境界、保存内容に件名が入らないこと）と、自明な写像を確認するだけのテストが混ざっている。**基準を決めずに増やしたので、基準を決めないと減らせない**
- **UI 部品に未使用のものがある。** 種別タブ（`TypeTabs`）は広い幅用に作ったが配線していない
- **`docs/implementation-plan.md` は設計としては精密だが要件を持たない。** 「誰が何をしたいか」「満たされたとどう分かるか」が無い。Phase 1 の完了条件 13 項目を追えなくなった原因
