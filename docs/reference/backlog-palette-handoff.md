## 1. 何を作るのか

Backlog（ヌーラボのプロジェクト管理ツール）向けのブラウザ拡張機能。`Cmd+K` で開くコマンドパレットから、キーボードだけでページ移動・課題ジャンプ・横断検索を行う。

**2 つのサーフェス、1 つのコンポーネント**

- **モーダル（行く）**: ページ・プロジェクト・スペース・課題キー・コマンド。ローカルデータのファジー一致のみで、打鍵ごとの API 呼び出しはしない
- **サイドパネル（探す）**: 課題・Wiki・ドキュメントのキーワード検索。結果が残り、プレビュー・履歴・共有 URL を持つ

同じ拡張ページを `?surface=modal` / `?surface=side` で出し分け、幅に応じてレスポンシブに切り替える。

**絶対に守る 5 つの原則**（詳細は仕様書 第 4 節）

1. 覚えるのは `Cmd+K` だけ。プレフィックスやモードは加速装置であって前提にしない
2. ナビゲーションと検索を優先。書き込み系は Phase 2
3. 文脈（現在プロジェクト・最近の閲覧・frecency）を並びに反映する
4. 日本語 IME を一級市民として扱う（`isComposing` 判定、全角記号の受理）
5. キーヒントは常時表示。発見可能性を犠牲にしない

## 2. アーキテクチャ（決定済み）

```
Backlog ページ                       拡張
┌──────────────────────┐            ┌──────────────────────────┐
│ content script        │ postMessage│ palette.html (iframe)     │
│  - iframe 注入・表示制御 │◀─────────▶│  - UI / 入力 / IME 処理     │
│  - Cmd+K 捕捉          │ open/close │                          │
│  - ページ外クリック検知   │ /resize   │        │ runtime.sendMessage
│  - URL コンテキスト送信  │            │        ▼                  │
│  - 表示キャッシュの収集   │            │ Service Worker            │
└──────────────────────┘            │  - 検索 / キャッシュ / 履歴  │
                                     │  - 認証情報・トークン更新     │
                                     │  - tabs.update で遷移       │
                                     └──────────────────────────┘
```

### 非交渉の実装制約

これらはセキュリティ設計上の決定であり、実装の都合で変えないこと。変更が必要な場合は理由を添えて確認を求める。

- **パレットの UI は content script が直接 DOM を作らず、拡張ページを iframe で表示する**。DOM・CSS・実行コンテキストを Backlog ページから分離する
- **content script が受け付けるメッセージは `open` / `close` / `resize` の 3 種のみ**
- **postMessage は双方向で origin を検証する**。content script 側は `event.source === iframe.contentWindow` かつ `event.origin === chrome-extension://<id>`。iframe 側は登録済みスペースのオリジンのみ。`targetOrigin` に `'*'` を使わない
- **認証情報・トークンは Service Worker のみが保持する**。UI 側にも content script にも渡さない
- **どのスペースの認証情報を使うかは Service Worker が `chrome.tabs` からタブ URL を直接見て決める**。ページから送られた値でトークンを選ばない
- **遷移は iframe → Service Worker → `chrome.tabs.update`**。ページ側を経由しない
- **`web_accessible_resources` は `use_dynamic_url: true`**。拡張ページの CSP は厳格化し、インラインスクリプトを使わない

## 3. Phase 1 の実装スコープ

### 3.1 やること

**モーダル**
- 課題キー直接ジャンプ（`PROJ-123` 形式、スペース横断。`123` のみは現在プロジェクトで補完）
- ページ移動
  - スペース系: ダッシュボード / お知らせ / 担当課題 / 個人設定
  - プロジェクト系: ホーム / 課題一覧 / 課題追加 / ボード / ガント / Wiki / ドキュメント / ファイル / Git・SVN / 設定
- プロジェクト切替、スペース切替
- コピーコマンド: 課題キー / 課題キー+件名 / Markdown リンク `[PROJ-123 件名](URL)` / URL
- 自由テキスト入力時、第一候補に「サイドパネルで検索」を固定表示
- 空状態: 最近開いた項目・最近の検索・現在プロジェクトのページ・担当課題

**サイドパネル**
- 課題・Wiki・ドキュメントの横断キーワード検索
- スコープ 3 段（このプロジェクト → このスペース → 全スペース）、Tab で循環
- 全スペース時はフラット表示 + スペースバッジ。現在スペース優先、以降は更新日時順
- プレビューペイン（広い幅のみ。狭い幅は選択行の展開）
- 検索状態の URL 共有（`#bl-search=<encoded state>`）と復元
- 検索履歴

**基盤**
- OAuth 2.0 接続（既定）+ API キー接続（フォールバック）、スペース単位
- 表示キャッシュ（`document.title` から件名を取得、API 不要）+ stale-while-revalidate
- 行動ログと frecency、クエリ → 結果の学習辞書
- ブラウザ履歴からの初回バックフィル（`optional_permissions`、オプトイン）
- 設定画面: 接続スペース管理 / 既定サーフェス / ショートカット / 学習オンオフ / 履歴消去 / 履歴取り込み

**キーバインド**

| キー | 動作 |
|---|---|
| `↑` `↓` / `Ctrl+N` `Ctrl+P` | 選択移動 |
| `Enter` | 開く（現在タブ） |
| `Cmd+Enter` | 新しいタブで開く |
| `Tab` | スコープ切替 |
| `Esc` | 1 階層戻る / 閉じる |
| `Backspace`（入力が空） | 前の階層へ |
| `↑`（入力が空） | 直前の検索クエリを再入力（サイドパネル） |
| `Cmd+→` | モーダルの入力をサイドパネルの検索へ昇格 |
| `Cmd+Shift+C` | 検索状態の URL をコピー（サイドパネル） |

### 3.2 やらないこと（Phase 2 以降）

実装中に「ついでに入れられそう」と思っても入れない。スコープを守り、必要なら提案として記録する。

- 課題への書き込み操作（ステータス変更・担当者変更・マイルストーン設定）
- お知らせのインライン既読
- 保存済み検索条件の登録
- ローマ字 → かな変換マッチ
- チーム共有のカスタムリンク
- 遷移パターン（共起）・時間帯による個人化
- Backlog 本体の全体検索の代替（足りないときは本体へ逃がす）
- Backlog 本体の UI を書き換える機能

## 4. 技術選定（提案。合意が必要）

以下は決定事項ではなく提案。Claude Code は着手前に妥当性を評価し、異論があれば代案を提示すること。

| 項目 | 提案 | 理由 |
|---|---|---|
| Manifest | MV3 | Chrome Web Store の要件 |
| 言語 | TypeScript | API レスポンス型とメッセージ契約を型で守りたい |
| UI | React or Preact | パレット UI は状態遷移が多い。バンドルサイズを重視するなら Preact |
| バンドラ | Vite + `@crxjs/vite-plugin` 相当 | MV3 の複数エントリ（content / SW / palette / options）を扱う |
| ファジー一致 | 軽量な自前実装または小型ライブラリ | 日本語対応が必要。既製品は英語前提が多いので要検証 |
| ストレージ | `chrome.storage.local` | 表示キャッシュ・行動ログ・接続情報 |
| テスト | Vitest（ロジック）+ Playwright（拡張の E2E） | キーバインドと IME の回帰を守りたい |
| 対応ブラウザ | Chrome 系を第一。Firefox はモーダルのみ（`sidebarAction` は挙動差） | Safari は `history` API がなく対象外 |

**推奨リポジトリ構成**

```
backlog-palette/
├─ src/
│  ├─ content/          # iframe 注入、Cmd+K 捕捉、表示キャッシュ収集
│  ├─ palette/          # 拡張ページ（モーダル / サイドパネル共通 UI）
│  ├─ background/       # Service Worker: 検索・認証・キャッシュ・遷移
│  ├─ options/          # 設定画面
│  ├─ shared/           # メッセージ契約の型、Backlog API クライアント、ランキング
│  └─ manifest.ts
└─ tests/
```

## 5. 未決事項（実装前に確認が必要）

| # | 項目 | ブロックする範囲 | 確認方法 |
|---|---|---|---|
| 1 | Backlog API の `keyword` がタイトルのみか本文にもマッチするか（課題 / Wiki / ドキュメント） | **サイドパネル検索の実装方針全体**。タイトルのみなら `plain` を取得してクライアント側フィルタという重い代替が必要 | 社内の Backlog API チームに確認、または検証用スペースで実測 |
| 2 | OAuth 2.0 の拡張向けリダイレクト URI（`https://<ext-id>.chromiumapp.org/`）を登録できるか | 認証を OAuth 既定にできるか | Backlog の OAuth アプリ登録画面で確認 |
| 3 | Backlog Enterprise での OAuth 可用性 | API キーフォールバックの必要範囲 | 製品仕様の確認 |
| 4 | Backlog エディタ内での `Cmd+K` の既存割り当て、既存単キーショートカット（j/k 等）との干渉 | content script のキー捕捉条件 | 実機で確認 |
| 5 | API レートリミットの実値 | 並列リクエスト数、デフォルトスコープ | ドキュメントと実測 |
| 6 | `chrome.commands` からの `sidePanel.open()` がユーザー操作起点として通るか、表示ラグ | サイドパネルの起動経路 | プロトタイプで検証 |
| 7 | クロスオリジン iframe へのフォーカス移譲（`open` 後の `input.focus()`） | パレットが機能するかの前提 | プロトタイプで検証 |
| 8 | 各ページの `document.title` 形式、SPA 遷移時の更新タイミング | 表示キャッシュの精度 | 実機で確認 |
| 9 | 非表示 iframe 常時注入のメモリ・初期化コスト | 注入戦略（常時 or 遅延） | タブ多数環境で計測 |

**#1、#6、#7 は最優先**。この 3 つは実装方針そのものを変える。まず薄いスパイクを作って潰すことを推奨する。

## 6. Claude Design のデータをどう使うか

### 取り込み手順

1. Claude Design のキャンバス右上 **Export → Handoff to Claude Code**（ローカルのコーディングエージェント宛 / Claude Code Web 宛）でバンドルを受け取る。スクリーンショットから起こすより情報が落ちない
2. あるいは Claude Code から Claude Design MCP サーバーに接続して直接読む:
   ```
   claude mcp add --scope user --transport http claude-design https://api.anthropic.com/v1/design/mcp
   ```
   追加後に `/design-login` でサインイン

### 取り扱いの注意

- **モックは 80 点の叩き台**。複数パターンが並んでいる箇所（結果行の密度、スコープ切替の表現、全スペース時のフラット vs グループ化、空状態の優先順位、2 段階コマンドの階層表現）は**まだ決着していない**。1 つを勝手に選ばず、実装しやすさの観点で意見を添えて確認を求めること
- **モックの寸法をそのままハードコードしない**。日本語の長い件名、狭いサイドパネル幅（380px）、キーヒントが 640px に収まらない場合を考慮する
- **モックに描かれていない挙動が多数ある**: 結果 0 件時の高さ、非同期で結果が追加されたときに選択位置がずれないこと、長い件名の省略とツールチップ、ローディング中の部分描画。実装時に判断が必要になったら記録して報告する

## 9. 推奨する進め方

1. **スパイク**: 未決事項 #6・#7 を潰す最小の拡張を作る（Cmd+K → iframe 表示 → フォーカス → Esc で閉じる、だけ）
2. **API 検証**: #1 を検証用スペースで実測し、サイドパネル検索の方針を確定
3. **モーダル先行**: API に依存しない部分（ページ移動・コマンド・空状態・表示キャッシュ）を先に完成させる。この時点で社内ドッグフーディングを始められる
4. **認証**: OAuth 接続を実装し、スペース管理を通す
5. **サイドパネル**: 検索・プレビュー・URL 共有・履歴
6. **個人化**: frecency、学習辞書、履歴バックフィル
7. **仕上げ**: エラー表現、ダークテーマ、設定画面、ストア提出物

3 の時点でモックの未決着パターンが実機で比較できるようになるので、そこで判断を確定させるとよい。
