# Claude Design 用プロンプト: Backlog Palette モック

使い方: まず「メインプロンプト」を投げて全体を出させ、その後「追いプロンプト」を必要な順に投げて揉んでいく。1 回で完成を狙わず、画面ごとに 2〜3 パターン出させて比較する前提。

---

## メインプロンプト

```
Backlog（ヌーラボのプロジェクト管理ツール）向けのブラウザ拡張機能「Backlog Palette」の UI モックを作ってください。Cmd+K で開くコマンドパレットと、キーワード検索用のサイドパネルの 2 つのサーフェスがあり、同じデザインシステム・同じコンポーネントを幅で出し分けます。

## プロダクトの要点
- 覚えるショートカットは Cmd+K だけ。プレフィックスやモードは前提にしない
- モーダル = 「行く」: ページ名・プロジェクト・スペース・課題キー（PROJ-123 形式）・コマンドをローカルで即マッチ。Enter で遷移して消える
- サイドパネル = 「探す」: 課題・Wiki・ドキュメントのキーワード検索。結果が残る、プレビューがある、履歴と共有 URL がある
- スコープは「このプロジェクト → このスペース → 全スペース」の 3 段で Tab で循環。全スペース時は結果をフラットに並べてスペースバッジを付ける
- 日本語 UI が主。件名やプロジェクト名は日本語、課題キーとページ種別は英字混在
- ターゲットは (1) 課題キーで会話する開発者/PM、(2) 複数スペースを横断する受託 PM・情シス、(3) 非開発職のヘビーユーザー。3 番目の人が迷わないことを最優先

## デザインの方向性
- Backlog のブランドグリーンをアクセントに、それ以外はニュートラルで控えめ。Backlog のページに重なる前提なので、本体より主張しない
- Linear / Raycast のコマンドパレットの密度感を参考に、行の高さは詰める。ただし日本語が窮屈にならない字間・行間
- ライト / ダークの両テーマ
- キーヒントは常に表示（フッター）。発見可能性を犠牲にしない
- アイコンは種別ごとに固定: 課題 / プロジェクト / ページ / Wiki / ドキュメント / ユーザー / コマンド / スペース

## 結果行の構成（共通コンポーネント）
種別アイコン ｜ 主テキスト（例: PROJ-123 ログイン画面のバリデーション修正）｜ 副テキスト（プロジェクト名 · ステータス · 担当者）｜ 右端にスペースバッジ（全スペース時のみ）とキーヒント（↵ / ⌘↵ / ›）
「›」は Enter を押してもパレットに留まって次の選択肢が出ることを示す（例: ステータス変更 › 処理中 / 処理済み）

## 作ってほしい画面

### A. モーダル（幅 640px 前後、ページ中央上寄り）
A1. 空状態: 上から「最近開いた」「現在のプロジェクト（Webリニューアル）のページ」「担当中の課題」。何も打たずに ↓ Enter で用が済む密度
A2. ページ名を入力中（例: 「ぼーど」）: ページ / コマンド がローカル一致で並ぶ
A3. 課題キーを入力中（例: 「PROJ-12」）: 直接ジャンプ候補が最上位に固定、その下に前方一致の課題
A4. 自由テキスト入力中（例: 「ログイン」）: 第一候補に「"ログイン" をサイドパネルで検索 ↵」を固定表示し、その下にローカル一致（ページ名・最近開いた課題の件名）
A5. スコープを「全スペース」に切り替えた状態: 入力欄左のスコープチップが変わり、結果にスペースバッジが付く
A6. 未接続スペースがある状態: 「acme は未接続 → 接続する」の行が末尾に出る
A7. コマンドの 2 段階操作: 「ステータスを変更 ›」を選んだ後、Esc で戻れる階層表示（パンくず的な表示）

### B. サイドパネル
B1. 狭い幅（380px）: 検索入力 + スコープ、最近の検索、結果一覧（種別セクション付き）。プレビューは選択行の展開で代替
B2. 広い幅（720px 以上、または別タブ表示）: 左に結果一覧、右にプレビューペイン（課題の詳細冒頭・コメント数・キーワードハイライト、ドキュメントの本文抜粋）
B3. 検索中のローディング: スペース単位で返ってきた順に描画されるので、「Webリニューアル: 12 件」「acme: 読み込み中…」「beta: 認証が切れています → 再接続」が同時に存在する状態
B4. 結果 0 件: 「Backlog 全体検索で開く」への逃げ道と、スコープを広げる提案
B5. フッターに「⌘⇧C 検索 URL をコピー」があり、コピー直後のトースト

### C. 周辺画面
C1. 初回体験: Cmd+K を押したが未接続。「このスペースを接続」の 1 行だけが出ているモーダル。ボタンは「OAuth で接続」を主、「API キーで接続」を副
C2. 設定画面（拡張のオプションページ）: 接続済みスペース一覧（認証方式・再接続・削除）、既定サーフェス（モーダル / サイドパネル）、ショートカット、学習のオン/オフ、履歴の消去、ブラウザ履歴からの取り込み（オプトイン、権限の説明付き）
C3. Backlog のページ上にモーダルが重なっている全景（背景は Backlog の課題一覧っぽいダミーで良い。実物の再現は不要）

## 出力形式
- 画面ごとに 1 フレーム。A / B / C のグループで並べる
- 各画面に短い注釈（何を検証したい画面か）を添える
- A1、A4、B2 は特に重要なので、それぞれ 2 パターン（例: セクション見出しあり / なし、スコープチップの位置が入力欄内 / 入力欄外）を出してください
- ダミーデータは日本語の現実的なもの。プロジェクト名は「Webリニューアル」「モバイルアプリ v3」「社内ヘルプデスク」、スペースは「nulab」「acme」「beta」、課題キーは PROJ- / MOB- / HELP-
```

## 追いプロンプト（揉むためのパターン出し）

順不同。気になるところから投げる。

### 情報密度と行の設計
```
結果行を 3 パターン出してください。(1) 1 行に主テキストと副テキストを横並び、(2) 2 行構成、(3) 主テキストのみで副情報はホバー時。日本語の長い件名（40 文字程度）が入ったときの省略の仕方も見たいです。
```

### スコープ切替の表現
```
スコープ（このプロジェクト / このスペース / 全スペース）の表現を 3 パターン出してください。(1) 入力欄左のチップ、(2) 入力欄下のセグメントコントロール、(3) 入力欄右のドロップダウン。Tab で循環することが伝わるヒントの出し方も含めて。
```

### 全スペース時の結果の見せ方
```
全スペース検索の結果表示を 2 パターン比較してください。(1) フラットに並べてスペースバッジを付ける、(2) スペースごとにグループ化。それぞれ 3 スペース × 数件の結果で。バッジの位置（左のアイコン横 / 右端）も試してください。
```

### 空状態の優先順位
```
モーダルの空状態を、想定ユーザー 3 タイプそれぞれに最適化した 3 パターンで出してください。(1) 開発者: 最近の課題が最上位、(2) 複数スペース横断 PM: プロジェクト / スペース切替が最上位、(3) 非開発職: 現在プロジェクトのページ一覧が最上位。共通のセクション構造で順序だけ変えて成立するか確認したいです。
```

### プレビューペイン
```
サイドパネルのプレビューペインを、課題 / Wiki / ドキュメントの 3 種別で出してください。共通のヘッダー（種別・キー・タイトル・プロジェクト）と、種別ごとの本文部分。キーワードハイライトの色はアクセントグリーンではなく別色にして、選択状態と混ざらないように。
```

### 2 段階コマンドの階層表現
```
「ステータスを変更 ›」→ 選択肢、のような 2 段階操作の階層表示を 3 パターン。(1) 入力欄左にパンくず（PROJ-123 › ステータス）、(2) 入力欄上に戻る行、(3) 結果リストの先頭に「← 戻る」行。Esc で戻れることをどう伝えるかも含めて。
```

### 未接続・エラーの表現
```
未接続スペース、認証切れ、レートリミット、オフラインの 4 状態を、モーダルとサイドパネルの両方で出してください。行内で完結させ、モーダル全体をエラー表示に切り替えない方向で。
```

### ダークテーマ
```
A1、A4、B2 をダークテーマで出してください。Backlog のページ自体はライトテーマのまま、その上にダークのモーダルが重なる組み合わせも 1 枚見たいです。
```

### 日本語入力中の見え方
```
入力欄に未確定の変換中テキスト（下線付き「ぼーど」）が入っている状態を出してください。変換中は結果を更新するか、確定まで待つかを見比べたいので、両方のパターンで。
```

### オンボーディング
```
初回インストール直後のフローを 3〜4 枚で。(1) Cmd+K を押すよう促すヒント（Backlog ページ上のトースト）、(2) 未接続モーダル、(3) OAuth 接続完了後の空状態、(4) 「ブラウザ履歴から最近の課題を取り込みますか？」のオプトイン。権限の説明文の置き方を含めて。
```

### ストア用スクリーンショット
```
Chrome Web Store 用のスクリーンショット（1280×800）を 4 枚。各枚に短いキャッチ（「Cmd+K でどこへでも」「スペースをまたいで検索」「開く前にプレビュー」「あなたに合わせて並ぶ」）を重ねた構成で。
```

## 揉むときの観点メモ

- 非開発職が A1 を見て「何を打てばいいか」が分かるか（プレースホルダーの文言が効く）
- A4 の「サイドパネルで検索」が第一候補にあることが、逆に「ページ名を打っただけなのに検索を勧められる」違和感を生まないか
- 全スペースのバッジが日本語件名と競合して読みにくくならないか
- フッターのキーヒントが 640px 幅で全部収まるか。収まらないときの優先順位
- ダークテーマでアクセントグリーンのコントラストが確保できるか
- サイドパネル 380px で 2 行構成の行が何件見えるか

## フィードバックを受けるためのプロンプト

生成した本人に聞くと自分の出力を擁護する方向にバイアスがかかるため、**スクリーンショットを書き出して、生成の文脈を持たない新しいチャットに投げる**のが最も素の指摘が返る。以下は基準を渡して採点させる形式。

### 評価基準を渡して採点させる

```
添付は Backlog（プロジェクト管理ツール）向けブラウザ拡張のコマンドパレット UI です。Cmd+K で開き、ページ移動・課題キーへのジャンプ・コマンド実行を行います。

以下の基準それぞれについて 5 点満点で採点し、減点した理由と具体的な改善案を挙げてください。褒める必要はありません。減点箇所だけ詳しく書いてください。

1. 覚えるのは Cmd+K だけで済むか（プレフィックスやモードの習得を暗黙に要求していないか）
2. 筋肉記憶を壊さないか（同じ入力で同じ結果が同じ位置に出ると信じられるか）
3. 非開発職のユーザーが、初見で「何を打てばいいか」分かるか
4. 情報密度は適切か（1 画面で判断できる件数 vs 読みやすさ）
5. 日本語の長い件名・プロジェクト名でレイアウトが破綻しないか
6. キーボードだけで完結するか（マウスを前提にした要素が混ざっていないか）
```

### タスクを歩かせる（認知的ウォークスルー）

```
添付の UI について、以下の 3 人がそれぞれのタスクを実行する過程を、1 打鍵ずつ追ってください。各ステップで「この人は次に何をすればいいか分かるか」「迷う可能性はどこか」を書き、最後に総打鍵数を出してください。

A. 開発者: Slack で「PROJ-1234 見て」と言われ、その課題を開く
B. 受託 PM: 別スペース（acme）の「請求」に関する課題を探し、URL をチームに共有する
C. 営業事務: 「Webリニューアル」プロジェクトのガントチャートを開く。ショートカットの知識はなく、この拡張を今日初めて使う

C の人が途中で諦める可能性がある箇所を特に厳しく見てください。
```

### パターンの比較と却下

```
添付は同じ画面の 3 パターンです。それぞれについて「どのユーザーにとって最良か」「どのユーザーにとって最悪か」を挙げ、最終的に 1 つを選んでください。選ばなかった案から、選んだ案に取り込むべき要素があれば指摘してください。

判断が拮抗している場合は「拮抗している」と正直に言い、決め手になる追加情報（何をユーザーテストで確かめるべきか）を挙げてください。
```

### 削らせる

```
添付の画面から要素を 2 つ削るとしたら、どれを削りますか。削った場合に失われる価値と、それでも削るべき理由を書いてください。

その上で、この画面に「足すべきもの」があるかを聞きます。ないなら「ない」と答えてください。
```

### 第一印象を取る

```
添付の画像を 5 秒だけ見たつもりで答えてください。

1. これは何をするための画面だと思いましたか
2. 最初に目が行った場所はどこですか
3. 次に何をすればいいと思いましたか

その後で、じっくり見た上での答えと、5 秒での答えがズレていた点を挙げてください。
```

### 実装との整合を確認する

```
添付の UI を実装する前提で、デザイン上は表現されていないが決めなければならない挙動を列挙してください。例: 結果が 1 件もないときの高さ、非同期で結果が追加されたときに選択位置がずれるか、長い件名のツールチップの有無。

デザインだけ見て「これは実装したら困る」と思う箇所があれば指摘してください。
```
