# Backlog Palette（Cmd+K 拡張機能）設計プラン

- 作成日: 2026-09-09
- フェーズ: UI・体験・機能群の定義（実装前）
- ゴール: Backlog で「行きたいページに行く」「探しているものを見つける」をキーボードだけで最短化するブラウザ拡張の設計を定める

---

## 1. 背景と課題

Backlog の現状には次のギャップがある。

- 既存のショートカットキーはユーザー設定でのオプトインが必要で、発見されにくい
- 課題キー（`PROJ-123`）で会話する文化があるのに、キーから課題へ最短で飛ぶ手段が弱い
- 複数スペースを横断するユーザー（受託 PM・情シス・管理者）はスペース切替とプロジェクト内ページの往復が多い
- 本体の全体検索は「検索状態を共有できない」「履歴が残らない」「都度読み込みで遅い」
- 非公式 Chrome 拡張が複数存在し、担当課題への到達・課題キー+件名のコピー・ステータス変更の短縮に明確な需要がある

## 2. 類似サービスから得た設計上の学び

| サービス | 学び |
|---|---|
| Linear | Cmd+K は「すべての操作を名前で呼べる受け皿」。単キーショートカットを忘れても Cmd+K に逃げられる。Esc で 1 階層戻るネスト構造 |
| Jira Cloud | 1 つのパレットで検索・アクション・移動を提供。`/` でコンテンツ検索に切替、結果は種類ごとにラベル分け。見つからなければ通常検索ページへ逃がす。入力欄フォーカス中は開かない（競合ルールを明示） |
| GitHub | デフォルト無効のベータが「利用率が低い」として廃止予告 → 反発で撤回。**発見可能性がなければ良い機能でも使われず消える** |
| Backlog 非公式拡張 | 担当課題一覧・お知らせ・課題キー+件名コピー・1 クリックのステータス変更が自作されている。ほぼ API キー入力を要求しており、これが普及の障壁 |

## 3. 想定ユーザー

1. **課題キーで会話する人**（開発者・PM）: Slack やレビューで渡された `PROJ-1234` へ 1 日数十回飛ぶ
2. **複数プロジェクト・複数スペースを横断する人**（受託 PM・情シス・管理者）: プロジェクト切替と ボード / ガント / Wiki の往復が多い
3. **非開発職のヘビーユーザー**（ディレクター・営業事務）: ショートカット文化はないが「探す手間」は同じく嫌う。記号プレフィックスや暗記を要求すると離脱する

拡張機能ならではの差別化は **スペース横断**。本体実装では越えられない壁を、設計の中心に置く。

## 4. 体験の原則

1. **覚えるのは Cmd+K だけ**。何も学ばずに「打てば出る」。プレフィックスやモードは加速装置であって前提にしない
2. **ナビゲーションと検索を優先し、書き込み系は後回し**。破壊的操作は確認 UI と Undo の設計が必要なので Phase 2
3. **文脈を反映する**。今いるプロジェクト・直近に開いた項目・担当課題が上に来る（frecency = 頻度 × 直近性）
4. **日本語 IME を一級市民として扱う**。Linear・Jira が弱い領域で Backlog が勝てる
   - 変換確定の Enter で遷移が発火しないよう `isComposing` を判定
   - 全角記号（＞ ／ ＠ ＃）を半角と同じプレフィックスとして受理
   - 日本語プロジェクト名に対し、プロジェクトキー（英字）でもマッチ
5. **ヒントは省かない**。GitHub の教訓から、フッターのキーヒントは常時表示

## 5. UI 設計

### 5.0 2 つのサーフェス（1 コンポーネント）

| サーフェス | 役割 | 特性 |
|---|---|---|
| **モーダル（行く）** | ページ・プロジェクト・スペース・課題キー・コマンド | 打鍵ごとの API 呼び出しなし。ローカルのファジー一致で即応答。Enter で消える |
| **サイドパネル（探す）** | キーワード検索（課題 / Wiki / ドキュメント） | 結果が残る。プレビューペイン、検索履歴、共有 URL の復元先。ページを行き来しても消えない |

- 同じ検索コンポーネントを幅で出し分ける。狭い（〜400px）: 1 カラム・行を圧縮。広い: 2 ペインで右にプレビュー
- モーダルに自由テキストを打つと、第一候補に「"○○" をサイドパネルで検索 ↵」を固定表示し、その下にローカル一致（ページ名・プロジェクト名・最近開いた課題の件名）を並べる
- サイドパネル表示中の Cmd+K はサイドパネルの入力欄にフォーカス
- 検索ロジック・キャッシュ・履歴は Service Worker に集約し、両サーフェスはメッセージで結果を受け取るだけにする
- サイドパネルは Chrome 系の付加価値と位置づけ、モーダルを最低保証にする（Firefox は `sidebarAction` で挙動が異なり、Safari にはない）

### 5.1 起動

- `Cmd+K`（Windows: `Ctrl+K`）。`chrome.commands` で登録し、ユーザーが変更可能にする
- Backlog のページ上ではオーバーレイ、Backlog 以外のページでは拡張ポップアップとして同じ UI を出す（どこからでも Backlog に飛べる）
- **要確認**: Backlog エディタ内での Cmd+K の既存割り当て、既存単キーショートカット（j/k 等）との干渉

### 5.2 モーダルの画面構成

```
┌──────────────────────────────────────────────────────┐
│ [このプロジェクト ▾]  ページ名、課題キー、コマンド…      │  ← 入力欄 + スコープ表示
├──────────────────────────────────────────────────────┤
│  🔍 "ログイン" をサイドパネルで検索                  ↵ │  ← 自由テキスト時の第一候補
│ ページ                                                │
│  ▤ ボード（Webリニューアル）                        ↵ │
│ 最近開いた課題                                        │
│  ◇ PROJ-123  ログイン画面のバリデーション修正           │
│              Webリニューアル · 処理中 · 田中          ↵ │
│ コマンド                                              │
│  › 課題キー+件名をコピー                             ↵ │
├──────────────────────────────────────────────────────┤
│ ↑↓ 移動  ↵ 開く  ⌘↵ 新しいタブ  Tab スコープ  Esc 閉じる │  ← 固定フッター
└──────────────────────────────────────────────────────┘
```

- **入力欄**: 左端にスコープ（このプロジェクト / スペース全体 / 全スペース）を表示し、Tab で循環
- **結果リスト**: 種類ごとにセクション分け。1 行 = 種類アイコン｜主テキスト｜副テキスト（プロジェクト・状態・担当）｜右端キーヒント
- **フッター**: キーヒントを常時表示

### 5.2.1 サイドパネルの画面構成（広い場合）

```
┌────────────────────────────┬─────────────────────────┐
│ 🔍 ログイン        [全スペース ▾]│ PROJ-123                │
│ 最近: バリデーション / リリース手順 │ ログイン画面のバリデーション修正│
├────────────────────────────┤ 処理中 · 田中 · 9/12 期限    │
│ 課題 (12)                   │                          │
│  ◇ PROJ-123 ログイン画面の…  │ …ログイン時に半角英数以外が │
│  ◇ PROJ-098 ログイン API…    │ 入力された場合の**ログイン**… │
│ Wiki (3)                    │                          │
│  ▦ ログイン仕様              │ コメント (4)               │
│ ドキュメント (2)             │  鈴木: 再現しました…        │
│  ▣ 認証フロー整理            │                          │
├────────────────────────────┴─────────────────────────┤
│ ↑↓ 移動  ↵ 開く  ⌘↵ 新しいタブ  ⌘⇧C 検索URLをコピー        │
└──────────────────────────────────────────────────────┘
```

- 狭い場合はプレビューを省き、選択行の展開で代替

### 5.3 空状態（何も入力していないとき）

- 最近開いた課題・プロジェクト・Wiki・ドキュメント
- 最近の検索クエリ
- 現在プロジェクトのクイックリンク（ホーム / 課題 / ボード / ガント / Wiki / ドキュメント / ファイル / Git / 設定）
- 担当中の未完了課題 上位 5 件

空状態は API を待たずに描画する。最近開いた項目はローカルの表示キャッシュ（6.7）から即時表示し、担当課題など API が必要なものは後から追記する。

「Cmd+K → ↓ → Enter」の 3 キーで用が済むケースを多く作る。

### 5.4 入力の解釈（プレフィックス不要の自動判定が基本）

| 入力 | 挙動 |
|---|---|
| `PROJ-123` 形式 | 課題への直接ジャンプを最上位に固定表示（スペース横断） |
| `123` のみ | 現在プロジェクトの課題として補完 |
| 通常テキスト | 第一候補に「サイドパネルで検索」。以下にページ名・プロジェクト名・コマンド名・最近開いた項目のローカルファジー一致（API 呼び出しなし） |
| 一致なし | 「サイドパネルで検索」のみ残る。サイドパネル側でも見つからなければ「Backlog 全体検索で開く」へ逃がす |

加速用プレフィックス（任意・全角も受理）:

- `>` コマンドのみ
- `@` ユーザー → その人の担当課題一覧へ
- `#` プロジェクトのみ

### 5.5 キーバインド

| キー | 動作 |
|---|---|
| `↑` `↓` / `Ctrl+N` `Ctrl+P` | 選択移動 |
| `Enter` | 開く（現在タブ） |
| `Cmd+Enter` | 新しいタブで開く |
| `Tab` | スコープ切替 |
| `Esc` | 1 階層戻る / 閉じる |
| `Backspace`（入力が空のとき） | 前の階層へ |
| `↑`（入力が空のとき） | 直前の検索クエリを再入力（サイドパネル） |
| `Cmd+→` | モーダルの入力をそのままサイドパネルの検索へ昇格 |
| `Cmd+Shift+C` | 検索状態の URL をコピー（サイドパネル） |

## 6. 横断全文検索の設計（サイドパネル）

キーワード検索はサイドパネルに閉じる。モーダル側は API を打鍵ごとに叩かないため、以下のレートリミットや速度の課題はサイドパネル内だけで扱えばよい。

### 6.1 データソース

| 対象 | API | 備考 |
|---|---|---|
| 課題 | `GET /api/v2/issues` (`keyword`) | 件名・詳細・コメントへの一致範囲を **要確認** |
| Wiki | `GET /api/v2/wikis` (`keyword`) | 同上 |
| ドキュメント | `GET /api/v2/documents` (`projectId[]`, `keyword`) | レスポンスに本文 `plain` を含む |
| プロジェクト / ユーザー | 一覧 API | 起動時に先読みしてローカルでファジー一致 |

### 6.2 本体の全体検索の弱点への対応

**共有できない → 検索状態を URL にシリアライズ**

- `https://{space}.backlog.com/dashboard#bl-search=<encoded state>` のようにフラグメントへ「クエリ・対象種別・プロジェクト・スペース」を埋める
- 拡張がフラグメントを読み、パレットを開いた状態で復元
- 拡張を入れていない相手にも通常の Backlog ページとして開けるので壊れない

**履歴がない → ローカル履歴**

- 検索クエリ履歴と「開いた結果」の履歴を `chrome.storage` に保存
- 空状態に「最近の検索」を表示、`↑` で直前クエリを再入力
- frecency ランキングと同じデータを使う

**遅い → 並列・逐次描画・キャッシュ**

- 種別ごと・スペースごとに並列リクエスト、返ってきた順にセクション単位で描画
- 同一クエリはセッション内キャッシュ、マスタ系（プロジェクト・ユーザー）は起動時に先読み
- 検索は Enter で明示的に実行（打鍵ごとの自動検索はしない）。サジェストは履歴とローカルデータのみ
- **レートリミット対策**: デフォルトスコープは「今のスペース」。全スペースはスコープ切替で明示的に広げる

### 6.3 プレビューペイン

- 広い幅では右ペインに選択中の課題（詳細・コメント冒頭）、Wiki、ドキュメント（`plain`）を表示し、キーワードをハイライト
- 「開いてみたら違った」を減らす。狭い幅では選択行の展開で代替

### 6.4 スニペットとハイライト

API はヒット位置を返さないため、`plain`（ドキュメント）や課題詳細から拡張側で切り出してハイライト表示する。本体より良い UX にできる余地。

### 6.5 スペース横断検索

- スコープは「このプロジェクト → このスペース → 全スペース」の 3 段。Tab で循環し、初期値は現在のスペース（Backlog 外から開いた場合は最後に使ったスペース）
- 特定スペースの直接指定はスコープチップから選択、または `space:acme`（任意プレフィックス、全角受理）
- スコープはセッション中保持し、Tab 2 回で「全スペース ↔ 現在スペース」を往復できる
- 全スペース時の結果はフラットにスペースバッジを付けて表示（グループ化しない）。並びは現在のスペース優先、その後は更新日時
- スペースごとに並列リクエストし、返ってきた順に描画。1 スペースの遅延・認証切れは行内エラーとして表示し、他のスペースの結果は妨げない
- 未接続スペースは結果末尾に「acme は未接続 → 接続する」を表示し、その場で接続できる
- レートリミットはスペース単位で独立。参加していないプロジェクトは API が返さないため権限考慮は不要

### 6.6 ローカルアクセスログによるパーソナライズ

拡張が Backlog 上の行動をローカルに記録し、結果の並びに反映する。サーバーには送らない。

**記録する信号**

| 信号 | 取得元 | 追加権限 |
|---|---|---|
| ページ閲覧（スペース / プロジェクト / 課題キー / ページ種別） | content script がロード時に URL から抽出 | 不要 |
| パレット内の行動（クエリ → 選択、スコープ切替、キャンセル） | 拡張ページ | 不要 |
| 検索（クエリ → クリック、プレビューのみで完了） | 拡張ページ | 不要 |

記録しないもの: ページ本文、コメント、検索結果の中身。行動ログは ID・キー・種別・タイムスタンプのみ。件名・プロジェクト名は行動ログとは分けて表示キャッシュ（6.7）に持つ。

**導出する個人化**

1. **frecency**: 課題・プロジェクト・ページの頻度 × 時間減衰。空状態と「最近開いた」の並びに使う
2. **クエリ → 結果の学習**: 打ったクエリと選んだ結果の対応をローカル辞書に蓄積し、次回同じクエリで上位に出す。表記ゆれや個人の略称を吸収
3. **遷移パターン**（Phase 2）: 「課題を開いた後はボード」「朝はダッシュボード → 担当課題」のような共起。空状態の候補に使う
4. **文脈スコープ**（Phase 2）: 現在プロジェクト・時間帯・曜日ごとの傾向

**並びへの介入ルール（筋肉記憶を壊さない）**

- 課題キー完全一致・コマンド名完全一致は個人化で動かさない（常に最上位）
- 個人化はセクション内の並びにのみ効かせ、セクションの順序は固定
- 「最近」と「よく使う」は別セクションにして混ぜない
- 学習が決め手になるのは同点・曖昧な場合のみ

**運用**

- `chrome.storage.local` に保存。保持期間と件数に上限（例: 90 日、エンティティ 5,000 件）、減衰で自然に消える
- 設定に「学習をオフ」「履歴を消去」を置く。空状態の行に「よく開くため」など理由を薄く表示
- デバイス間同期はデフォルトなし。同期する場合は `storage.sync`（100KB 上限）に収まるクエリ辞書のみ
- 生ログは Service Worker に閉じ、ページにも UI にも渡さない（9 節と整合）

### 6.7 表示キャッシュ（API を呼ばずに「最近見た課題」を出す）

空状態や「最近開いた」セクションを API 往復なしで即描画するため、閲覧時に表示に必要な最小情報をローカルに保存する。

- content script がページロード時に、URL から課題キー、`document.title` から件名とプロジェクト名を抽出し、`{space}/{PROJ-123} → { 件名, プロジェクト, 最終閲覧 }` として保存。API は呼ばない
- Wiki・ドキュメント・プロジェクトページも同じ方式で「最近見た Wiki」「最近のプロジェクト」に使う
- 空状態と「最近開いた」はこのキャッシュだけで描画。未接続スペース、認証前、オフラインでも表示できる
- **stale-while-revalidate**: 画面に表示した項目だけを裏で API から再取得し、件名の変更やステータス・担当者（タイトルから取れない）を差し替える。接続済みスペース限定
- `document.title` の形式依存になるため、抽出処理は 1 箇所に閉じ、失敗時は課題キーのみの表示にフォールバック
- 保持上限・減衰・「履歴を消去」は行動ログ（6.6）と共通。本文・コメントは持たない

**ブラウザ履歴からの取り込み（オプトイン）**

- `chrome.history.search()` は URL・タイトル・訪問回数・最終訪問時刻を返すため、`backlog.com/view/` 等を含む履歴から課題キー・件名・frecency の材料を自前ログなしで得られる。インストール前の履歴も含まれ、Chrome 同期が有効なら他デバイスの閲覧も入る
- ただし `history` 権限はインストール時に「閲覧履歴の読み取り」の警告が出て、企業ポリシーや非開発職ユーザーの心理的障壁になる。パレット内の行動（クエリ → 選択）は履歴に残らないため、学習用の自前記録はいずれにせよ必要
- 方針: 既定は表示キャッシュ（追加権限なし）。`optional_permissions` に `history` を入れ、オンボーディングと設定に「ブラウザ履歴から最近の課題を取り込む」を置き、押したときだけ `permissions.request()` で権限を求める
- 許可後は過去 90 日分を表示キャッシュにバックフィルする用途に限定し、平常時の記録は自前ログ 1 本に統一する（挙動を読みやすくする）
- Enterprise のカスタムドメインは登録済みスペースから検索対象に加える。Safari には `history` API がないため対象外

## 7. 機能群とフェーズ

### Phase 1（このフェーズで定義し実装する範囲）

- 課題キー直接ジャンプ（スペース横断）
- ページ移動
  - スペース系: ダッシュボード / お知らせ / 担当課題 / 個人設定
  - プロジェクト系: ホーム / 課題一覧 / 課題追加 / ボード / ガント / Wiki / ドキュメント / ファイル / Git・SVN / 設定
- プロジェクト切替、スペース切替
- サイドパネルでの横断キーワード検索: 課題、Wiki、ドキュメント（プレビュー付き）
- 検索状態の URL 共有、検索履歴（サイドパネル）
- モーダル → サイドパネルへの昇格動線
- 空状態: 最近の項目・最近の検索・担当課題、frecency ランキング、クエリ → 結果の学習辞書
- ローカルアクセスログの記録と「学習オフ / 履歴消去」設定
- 表示キャッシュによる API 不要の「最近見た課題 / Wiki / プロジェクト」（stale-while-revalidate）
- ブラウザ履歴からの初回バックフィル（オプトイン、`optional_permissions`）
- コピー系コマンド: 課題キー / 課題キー+件名 / Markdown リンク `[PROJ-123 件名](URL)` / URL
- キーバインド一式（5.5）

> ドキュメント検索は `keyword` の仕様確認結果によって Phase 1 か 1.5 に振り分ける

### Phase 2（設計だけ先にしておく）

- 課題への操作: ステータス変更 / 自分を担当者に / マイルストーン設定（Jira の「パレットに留まる 2 段階操作」を踏襲、Undo 付き）
- お知らせのインライン既読
- 保存済み検索条件（フィルタ URL）の登録と呼び出し
- ローマ字 → かな変換マッチ（`kyak` → 顧客）
- パーソナライズの拡張: 遷移パターン（共起）、時間帯・曜日の文脈スコープ
- チーム共有のカスタムリンク（例: 「リリース手順」→ 特定 Wiki）

### スコープ外

- 本体の全体検索の完全な代替（拡張の検索で足りないときは本体へ逃がす）
- Backlog 本体の UI を書き換える機能

## 8. 認証の設計

スペース単位の「接続」として OAuth 2.0 と API キーの両方を持ち、検索側は認証方式を意識しない共通インターフェースで扱う。

| 方式 | 位置づけ | 備考 |
|---|---|---|
| **OAuth 2.0（デフォルト）** | スペースごとに「接続」ボタン 1 回 | `chrome.identity.launchWebAuthFlow` で認可コードフロー。リフレッシュトークンは Service Worker が管理。キーのコピペが不要で非開発職にも通る。公式拡張として OAuth アプリを登録 |
| **API キー（フォールバック）** | Backlog Enterprise（オンプレ）、OAuth を組織で制限している環境、CLI 感覚で使いたいユーザー | スペース追加画面で「API キーで接続」を選択 |

- 初回体験: Cmd+K → 未接続なら「このスペースを接続」の 1 行だけ表示 → クリックで OAuth
- トークン失効時はサイドパネル側でスペース単位の再接続導線を出す
- API キーは `chrome.storage.local` に保存されるため平文である旨を設定画面に明記し、いつでも削除できるようにする
- セッション Cookie の流用は採用しない（認証モデルを 1 本に単純化）

## 9. アーキテクチャとセキュリティ

パレットは content script が直接描画せず、**拡張ページを iframe で表示**する。DOM・CSS・実行コンテキストを Backlog ページから完全に分離し、認証情報や検索結果がページのコンテキストに入らないようにする。サイドパネルも同じ拡張ページを `?surface=side` で表示し、「1 コンポーネント・2 サーフェス」を実装レベルで成立させる。

```
Backlog ページ                       拡張
┌──────────────────────┐            ┌──────────────────────────┐
│ content script        │ postMessage│ palette.html (iframe)     │
│  - iframe 注入・表示制御 │◀─────────▶│  - UI / 入力 / IME 処理     │
│  - Cmd+K 捕捉          │ open/close │                          │
│  - ページ外クリック検知   │ /resize   │        │ runtime.sendMessage
│  - URL コンテキスト送信  │            │        ▼                  │
└──────────────────────┘            │ Service Worker            │
                                     │  - 検索 / キャッシュ / 履歴  │
                                     │  - 認証情報・トークン更新     │
                                     │  - tabs.update で遷移       │
                                     └──────────────────────────┘
```

### 9.1 content script の責務を最小化

- やること: iframe 注入、Cmd+K 捕捉、ページ外クリック検知、現在 URL のコンテキスト送信、iframe の表示 / 非表示 / 高さ調整
- やらないこと: API 呼び出し、認証情報の保持、ページ遷移
- 受け付けるメッセージは `open` / `close` / `resize` の 3 種のみ
- 遷移は iframe → Service Worker → `chrome.tabs.update`。ページ側を経由しない

### 9.2 postMessage の検証

- content script 側: `event.source === iframe.contentWindow` かつ `event.origin === chrome-extension://<id>` を必須
- iframe 側: `event.origin` が登録済みスペースのオリジン（`*.backlog.com` / `*.backlog.jp` / Enterprise のカスタムドメイン）に一致するものだけ処理
- `targetOrigin` は常に明示。`'*'` は使わない

### 9.3 ページ由来の情報はヒント扱い

- スペース・プロジェクトキー・課題キーなどのコンテキストはスコープ初期値とランキングにのみ使い、認証の選択には使わない
- 使用する認証情報は Service Worker が `chrome.tabs` からタブ URL を直接参照して決定する。ページが送った値でトークンを選ばない

### 9.4 開閉とフォーカス

- iframe はページ読み込み時に非表示で先に注入し、初回 Cmd+K のロード遅延を消す
- `open` を受けた iframe が自身で `input.focus()`。以降のキー入力は iframe に閉じるため、Backlog の単キーショートカット（j/k 等）が誤爆しない
- Esc は iframe 内で受けて `close` を送信。ページ外クリックは content script が検知して iframe に `close` を送り、iframe が状態をクリア後に非表示
- 高さは iframe が `resize` を送り、content script 側で上限をクランプ

### 9.5 その他

- `web_accessible_resources` は `use_dynamic_url: true` でフィンガープリントを避ける
- 拡張ページの CSP は厳格化、インラインスクリプトなし
- API キー・トークンは Service Worker からのみアクセスし、UI 側には渡さない
